# Durable Reels Pipeline Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Replace request-bound automation with durable, observable VPS execution.
**Architecture:** Next.js writes jobs to SQLite; a separate Node worker claims them transactionally, checkpoints preparation and publishes each destination independently.
**Tech Stack:** TypeScript, Node LTS, SQLite/better-sqlite3, Next.js stable, Bright Data, Gemini, FFmpeg, S3/R2.
**Spec:** `docs/superpowers/specs/2026-10-28-pipeline-design.md` (approved by user: “pode continuar”).

## Global Constraints

- Preserve legacy users, sources, settings, reels, external IDs and media.
- No credentials crossing users; no HTTP request doing background publication.
- Single VPS/local SQLite; bounded heavy processing concurrency.
- Never blindly retry an uncertain external publication or paid collection trigger.
- Native execution approved by continuing the proposed rebuild; do not ask again for routine implementation decisions.

## Review Focus

- Expired leases and stale completions: real SQLite claim/fencing tests in Task 1.
- Crash after external submission: persisted publication phase tests in Task 3.
- Missing credentials followed by reconnection: blocked/reactivation tests in Tasks 3–4.
- Legacy migration, duplicate platform IDs and shared files: migration/media tests in Tasks 1–2.
- SSRF, redirects, resource exhaustion, malformed providers: URL/download and contract tests in Tasks 2–3.
